# MelonAI 创作工作台

这是你与 Obsidian 知识库（`D:\DatasPath\Knowledge`）之间的创作桥梁。
调用后显示菜单，让你选择要做什么。

## 知识库路径（固定）

```
知识库根目录：D:\DatasPath\Knowledge
raw/          → D:\DatasPath\Knowledge\raw\              （收件箱，只存不整理）
MelonAI/      → D:\DatasPath\Knowledge\wiki\MelonAI\     （结构化知识）
  概念笔记/   → ...\MelonAI\概念笔记\                      （从 raw 提炼的素材）
  已产出/     → ...\MelonAI\已产出\                        （每期视频完整记录）
  创意池.md   → 所有灵感的 backlog
  话题地图.md → 话题关系网和空白区
  提示词模板库.md → 积累的 prompt 模板
脚本项目根   → d:\DatasPath\Claude\视频文案创作\
generate_script.py → 脚本项目根\generate_script.py        （Deepseek 自动生成）
```

## 入口：显示菜单

当用户输入 `/melona` 时，显示：

```

[1] 创作新视频     — 从灵感讨论到产出完整创意记录
[2] 提炼 raw/ 素材 — 把收件箱里的资料整理成结构化笔记
[3] 挖掘新话题     — 从已有内容中推荐未覆盖的方向

[5] 清理 raw/      — 标记/整理已处理的 raw 文件

你想做什么？(1-5)
```

## 🎬 流程 1：创作新视频

### Step 1：引导讨论收集信息

跟用户对话，帮他把散落的想法梳理成：

```
核心主题：[一句话观点/反差/钩子]
目标观众：[具体画像]
关键要点：[3-5 个必须覆盖的点，逐条列出]
CTA：[希望观众做什么]
```

引导问题时可以用的角度：
- "你最想让观众看完记住的一句话是什么？"
- "这个视频跟别人讲同样的主题有什么不同？"
- "你自己最有感触的瞬间是哪个？"

### Step 2：选框架 + 语气

帮用户推荐：

| 内容类型 | 推荐框架 |
|---------|---------|
| 个人经历/踩坑/成长 | 3幕故事法 |
| 观点输出/方法论 | 钩子-展开-收尾 |
| 解决痛点 | PAS 痛点驱动 |
| 安利/推荐 | AIDA |

语气选项：口语轻松 / 激情澎湃 / 专业深度 / 幽默风趣 / 温暖治愈

### Step 3：生成初版文案（双模式）

**模式 A — 快速生成（主题明确时）：**
```
把梳理好的信息填入 generate_script.py 的输入，运行脚本：
cd "d:/DatasPath/Claude/视频文案创作" && python generate_script.py << 'EOF'
[核心主题]
[目标观众]
[关键要点1]
[关键要点2]
...
[空行结束要点]
[CTA]
[框架编号]
[语气编号]
n
EOF
```
生成的文件自动保存到 `MelonAI/已产出/` 目录，文件名格式 `YYYYMMDD_HHMMSS_主题.md`。

**模式 B — 深度打磨（用户想边聊边写时）：**
直接由你（Claude）根据用户提供的信息和框架，写出一版60秒以内的口播文案。
写作原则：
- 口语化，像在跟朋友聊天
- 开头5秒必须有钩子（反常识/好奇/痛点）
- 每句话都有信息量，不堆砌形容词
- 严格按照选定的框架和时间分配
- 画面建议要具体可执行
- 收尾有 CTA

### Step 4：迭代优化

展示文案给用户，问：
- "整体感觉对吗？有没有什么地方想改？"
- "语气是不是你想要的调调？"
- "有没有你实际经历中更生动的细节想加进去？"

然后根据反馈修改，直到用户满意。

常见优化方向：
- 砍掉功能细节，保留情绪（视频不是产品说明书）
- 把书面语改成更像"你"说话的方式
- 加强开头钩子的反差感
- 调整某段太长/太短

## 🔍 流程 3：挖掘新话题

### Step 1：读取已有内容

- 读取 `MelonAI/已产出/` 所有文件的标题和标签
- 读取 `MelonAI/概念笔记/` 的话题分布
- 读取 `MelonAI/话题地图.md` 的空白区
- 检查 `raw/` 最新素材

### Step 2：分析推荐

从以下角度挖潜：

| 角度 | 说明 |
|------|------|
| **缺失覆盖** | 话题地图里有但还没产出的方向 |
| **纵向深挖** | 已产出话题的某个子角度还没讲 |
| **横向串连** | 两个独立话题之间有联系但还没讲过 |
| **热点跟进** | raw/ 里出现的新概念 |
| **反馈驱动** | 用户可能被问过的问题 |

### Step 3：更新创意池

将推荐的话题写入 `创意池.md` 的"待创作"表格，标注优先级和想法来源。

## 🧹 流程 5：清理 raw/

### Step 1：检查标记

扫描 `raw/` 中所有文件，检查末尾是否有"处理记录"标记。

### Step 2：展示分类

列出给用户看：

```
📥 raw/ 当前状态：
  ✅ 已处理（有标记）: 3 个
  ⏳ 未处理: 2 个
  🗑️ 可清理（已经处理且超过30天）：1 个
```

### Step 3：执行清理

根据用户选择：
- 已处理的文件可移到 `raw/archive/`（不清除，只是归档）
- 超过30天且用户确认无用的可删除


## 工作原则

1. **一切以知识库为准**：创意记录、素材、索引都在 Obsidian 中，脚本项目只是辅助工具。
2. **raw/ 只读不写**（加处理标记除外）：原始资料不修改内容，只追加处理记录。
3. **每条记录要完整**：创意记录必须包含从想法到定稿的全部链路，缺哪步补哪步。
4. **双向链接要到位**：每条记录跟 [[创意池]] [[话题地图]] 和其他关联笔记之间要有链接。
5. **每做完一步更新一步**：不要攒到最后一口气更新所有索引。
